## Task

Implement the 4 bug fixes for MSP/Serial communication deadlock issue that has caused 6 plane crashes. Developer has already investigated and identified all bugs - now implement the fixes.

## Background

Flight controller freezes completely when MSP reader (Configurator) disconnects while LOG_DEBUG is enabled. Investigation identified 4 interconnected bugs:

1. **BUG #1 (CRITICAL):** `serialIsConnected()` missing return statement
   - File: `src/main/drivers/serial.c:111-118`
   - Function calls `isConnected()` callback but ignores return value
   - Always returns `true` even when port is disconnected

2. **BUG #2 (CRITICAL):** Infinite loop in `waitForSerialPortToFinishTransmitting()`
   - File: `src/main/io/serial.c:505-510`
   - No timeout - spins forever if TX buffer never empties

3. **BUG #3 (HIGH):** Infinite busy-wait in `printf.c`
   - File: `src/main/common/printf.c:229, 288`
   - Busy-wait loops with no timeout

4. **BUG #4 (HIGH):** `mspLogPort` never cleared on disconnection
   - File: `src/main/common/log.c:140-141`
   - Port reference set once, never cleared when disconnected

**Impact:** 6 plane crashes reported on MATEK F405 Wing V2. Developer confirmed F7 and H7 boards also affected.

## What to Do

1. **Phase 1: Apply Critical Fixes (FIX #1 + #2)**
   - Fix `serialIsConnected()` return statement (1 line)
   - Add timeout to `waitForSerialPortToFinishTransmitting()` (5 lines)

2. **Phase 2: Apply Secondary Fixes (FIX #3 + #4)**
   - Add timeout to `printf.c` busy-wait (3 lines per location)
