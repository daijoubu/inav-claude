# INAV 9.1.0 Release Checklist

**Version:** 9.1.0 (minor release — no full chip erase required for 9.x → 9.1.0 upgrades)
**Source branches:** `maintenance-9.x` (both firmware and configurator)
**Tag pattern (RC):** `9.1.0-RC1`, `9.1.0-RC2`, etc.
**Tag pattern (final):** `9.1.0`
**Downloads directory:** `claude/release-manager/downloads/`

> ⚠️ **IMPORTANT:** Each phase below starts with a mandatory guide re-read step.
> Do NOT skip these — guides must be fresh in context at the time each phase executes.
> Reading all guides up-front is NOT sufficient.

## Phase 1: Configurator Version Bump + SITL PR

> 📖 **Re-read guide NOW before starting this phase:**
> ```bash
> cat claude/release-manager/guides/1-workflow-and-preparation.md
> ```
> Also read:
> ```bash
> cat claude/release-manager/guides/4-building-locally.md
> ```

### 1.1 — Assess SITL Changes

- [ ] Check if firmware SITL source changed since last release tag:
  ```bash
  cd inav
  git diff 9.0.1..HEAD -- src/main/target/SITL/
  ```
- [ ] **If SITL source changed:** continue to 1.2 to update binaries
- [ ] **If SITL source unchanged:** skip to 1.4 (only version bump needed in PR)

### 1.2 — Build Linux x64 SITL Locally (if needed)

- [ ] Build on Ubuntu 22.04 LTS (glibc 2.35) for maximum compatibility — use the `inav-builder` agent:
  ```
  Agent: inav-builder
  Prompt: "Build SITL with -DCMAKE_BUILD_TYPE=Release on maintenance-9.x"
  ```
- [ ] Verify glibc version of built binary is ≤ 2.35:
  ```bash
  objdump -T inav/build/inav_SITL | grep GLIBC | sed 's/.*GLIBC_//;s/ .*//' | sort -V | tail -1
  # Expected output: 2.35 or lower
  ```

### 1.3 — Download Other SITL Platforms from Nightly

- [ ] Find the nightly release matching the target firmware commit:
  ```bash
  gh release list --repo iNavFlight/inav-nightly --limit 10
  ```
- [ ] Download SITL resources:
  ```bash
  mkdir -p downloads/sitl-9.1.0-RC1
  gh release download <nightly-tag> --repo iNavFlight/inav-nightly \
    --pattern "sitl-resources.zip" -D downloads/sitl-9.1.0-RC1/
  unzip downloads/sitl-9.1.0-RC1/sitl-resources.zip -d downloads/sitl-9.1.0-RC1/
  ```
- [ ] Update SITL binaries in configurator repo:
  ```bash
  cd inav-configurator
  cp ../inav/build/inav_SITL resources/public/sitl/linux/           # locally built
  cp <nightly-extract>/sitl/linux/arm64/inav_SITL resources/public/sitl/linux/arm64/
  cp <nightly-extract>/sitl/macos/inav_SITL resources/public/sitl/macos/
  cp <nightly-extract>/sitl/windows/inav_SITL.exe resources/public/sitl/windows/
  # NOTE: Do NOT overwrite cygwin1.dll unless toolchain changed
  ```

### 1.4 — Create Configurator Version Bump PR

- [ ] Create branch from `maintenance-9.x`:
  ```bash
  cd inav-configurator
  git checkout -b version-bump-9.1.0 upstream/maintenance-9.x
  ```
- [ ] Bump version (if not already done):
  ```bash
  npm version 9.1.0 --no-git-tag-version
  ```
- [ ] If SITL updated: stage SITL binaries:
  ```bash
  git add resources/public/sitl/
  git commit -m "Update SITL binaries for 9.1.0"
  ```
- [ ] Commit version bump:
  ```bash
  git add package.json package-lock.json
  git commit -m "Bump version to 9.1.0"
  ```
- [ ] Push and create PR:
  ```bash
  git push -u origin version-bump-9.1.0
  gh pr create --title "Version bump to 9.1.0" \
    --body "Version bump and SITL binary update for 9.1.0 release" \
    --base maintenance-9.x --repo iNavFlight/inav-configurator
  ```
- [ ] Wait for configurator CI to pass on the PR
- [ ] Merge the PR

## Phase 4: Verify Artifacts

> 📖 **Re-read guide NOW before starting this phase:**
> ```bash
> cat claude/release-manager/guides/3-verifying-artifacts.md
> ```

### 4.1 — Verify macOS DMGs (Cross-Platform Contamination Check)

- [ ] Run the DMG verification script on both DMG files:
  ```bash
  ./claude/release-manager/verify-dmg-contents.sh \
    claude/release-manager/downloads/configurator-9.1.0-RC1/macos/*.dmg
  ```
- [ ] **PASS criteria:** No `.exe`, `.dll`, or `.msi` files found; only `sitl/macos/` directory present
- [ ] Verify arm64 DMG is arm64 architecture and x64 DMG is x86_64 — filenames must match
- [ ] **If contamination found:** DO NOT proceed — investigate and rebuild configurator artifacts

### 4.2 — Verify Windows SITL (cygwin1.dll)

- [ ] Run Windows SITL verification script:
  ```bash
  ./claude/release-manager/verify-windows-sitl.sh \
    claude/release-manager/downloads/configurator-9.1.0-RC1/windows/INAV-Configurator_win_x64_9.1.0.zip
  ```
- [ ] **PASS criteria:** Both `cygwin1.dll` (~2.9 MB) and `inav_SITL.exe` (~1.5 MB) present in `resources/sitl/windows/`
- [ ] **If cygwin1.dll missing:** DO NOT release — check configurator repo at `resources/public/sitl/windows/`

### 4.3 — Verify Linux SITL glibc Compatibility

- [ ] Check maximum glibc version required (must be ≤ 2.35):
  ```bash
  objdump -T claude/release-manager/downloads/sitl-9.1.0-RC1/resources/sitl/linux/inav_SITL \
    | grep GLIBC | sed 's/.*GLIBC_//;s/ .*//' | sort -V | tail -1
  ```
- [ ] **PASS:** Output is `2.35` or lower
- [ ] **If too high:** Build Linux x64 SITL locally on Ubuntu 22.04 LTS (see Phase 1.2), replace the binary, create a new PR, rebuild configurator artifacts

### 4.4 — Human Functional Testing (Cannot Be Automated)

- [ ] **HUMAN REQUIRED — test on Windows:** Extract Win64 zip, launch configurator, verify demo mode and USB FC connection work
- [ ] **HUMAN REQUIRED — test on Linux:** Extract Linux zip, launch configurator, verify demo mode and USB FC connection work
- [ ] **SITL test:** Launch SITL from Configurator, verify it starts and connects without errors
- [ ] **SITL version check:** Confirm SITL version shown in configurator matches `9.1.0`
- [ ] macOS test if available

## Repeat Protocol for Each RC

For RC2, RC3, etc., repeat all phases with the new RC number, then:

- Release notes: cumulative format (add new "Changes in RC*N*" section at top of previous RC notes)
- Wiki: add new RC section at top of `inavwiki/9.1.0-Release-Notes.md`
- PG validation: re-run for each RC
- All verification steps: repeat in full

When releasing the **final (non-RC) 9.1.0**:

- [ ] Omit `--prerelease` flag in `gh release create`
- [ ] Release notes use **summary pattern** (NOT cumulative RC listing):
  - "Changes since last RC" at top
