## ⚠️ Branch-topology note (read first)

`9.1.0-RC1` shipped 2026-06-05 from `maintenance-9.x`. **`maintenance-9.x` (firmware) was subsequently corrupted and retired**: someone used GitHub's web "Resolve conflicts" tool on a PR based on it, which merged the entire base branch (`maintenance-10.x`) into `maintenance-9.x` — the exact wrong-direction accident guides 1 and 7 warn about. This is not a hypothetical risk in this repo; it already happened once. `release/9.1` was cut as the clean replacement active branch and is the one that has carried all real 9.1 work since.

- `release/9.1` has **292 commits** `maintenance-9.x` doesn't (RC1 prep + all post-RC1 fixes — this is the real, uncorrupted 9.1 content)
- `maintenance-9.x` has **93 commits** `release/9.1` doesn't — these are **not** salvageable 9.2 work to reconcile; they include the maintenance-10.x contamination from the bad merge. **Do not merge, diff-recover, or reconcile anything from `maintenance-9.x` back into `release/9.1`.** Treat `maintenance-9.x` as dead.

**This release must be built from `release/9.1`, not `maintenance-9.x`.** The existing RC1 checklist (`../9.1.0-RC1/9.1RC1-release-checklist.md`) still says `maintenance-9.x` — that's now stale/wrong for this repo and should be corrected or annotated so nobody follows it literally next time.

The configurator repo has **no** `release/9.1` branch and was not affected — `maintenance-9.x` is still its only active branch (18 commits ahead of its master) and remains correct to use there.

**Resolved (no longer an open question):** future 9.1.x patch work for firmware should target `release/9.1`, not `maintenance-9.x`. Confirm with Manager/Developer whether `maintenance-9.x` (firmware) should be deleted outright or just left untouched as a cautionary artifact — either way, nothing should ever be merged out of it again.
